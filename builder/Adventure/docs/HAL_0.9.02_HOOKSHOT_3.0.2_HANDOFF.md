## What changed upstream and the first porting issue

The local v3.0.2 history contains three commits after the v3.0.0 baseline. Comparing those exact commits reports 10 changed files:

1. v3.0.1 (`ddf11e0f`) fixes Linux item-wheel text using `gpu/vk/vk_wheel_text.h`, changes `gpu/vk/vk_wheel.cpp`, adds the wheel to ImGui header dependencies in `nx2/build.py`, and adds `tests/test_wheel_text.py` and `tests/test_wheel_text.cpp`.
2. v3.0.2 (`a2b7f979`) fixes rolling while holding forward by removing the stick direction pseudo-buttons from `host/nn_hid.c`. It updates input-background tests and deletes the now-obsolete `tests/test_stick_buttons.py`. Preserve that input fix and test rolling while moving; do not reintroduce the old bits.
3. The intervening documentation commit adds the Features, Builder Mods + Editor, and save-editor descriptions. In 3.0.2 the stock Builder’s save editor is documented as a **Windows Builder** feature; in-game Debug inventory tools are separate. HAL’s own in-place editor is part of the requested cross-platform launcher and must be preserved.

4. Verify the native capability files are truthful for the code actually built: `hookshot_randomizer_capability.txt` (`HOOKSHOT_DEV_RANDOMIZER=1`), `hookshot_starting_inventory_capability.txt` (`HOOKSHOT_STARTING_INVENTORY=6`), `hookshot_child_stealth_capability.txt` (`HOOKSHOT_CHILD_STEALTH=1`) and `hookshot_stone_reward_capability.txt` (`HOOKSHOT_STONE_REWARD=1`). 5. Preserve the shipped alpha’s functional boundaries and user choices, not just the UI: save-slot switching, clickable inventory, age, hearts, magic, songs, progressive items/bags, bottle contents, trade-item/mask separation and Zora scale; granting a bow or slingshot must grant the basic corresponding ammo capacity without downgrading an existing bag. 6. Preserve fixed seed/profile identity and pool accounting. Starting items displaced from supported chest rewards become blue rupees; do not force the Kokiri Sword chest to hold the sword. For closed forest, the sword must be reachable in Kokiri and the slingshot in Kokiri or reachable Deku checks under the selected settings. Do not claim the current solver proves full-game beatability. Ship of Harkinian is the desired feature/logic reference; keep unimplemented options and trackers hidden rather than advertising them as working.
7. Revalidate the experimental Lost Woods target, Saria’s Ocarina and Skulltula one-time reward exchanges; they are limited exchanges, not a general event shuffle. Skulltula milestone settings must not be described as enforced by the current solver. Check child stealth’s Zelda’s Letter and Lullaby, Gohma intro, Deku exit and stone, journal messages, access toggles and F9 trace status. Use the local F9 logs and request new ones when a specific event cannot be identified; do not publish logs or game resources.
8. Preserve the tested experimental 20-bombchu capacity without a bomb bag. Ammo chest handling is **not** fixed for ordinary launches: arrows, bombs or seeds can still be awarded without their capacity. The desired fallback is a blue rupee when the item cannot be held, with matching model, text and saved reward; the stock Hylian Shield chest’s conditional mechanism is promising but not yet wired into ordinary launches. Test missing/owned capacity, acquired upgrades, each ammo type, large/small chests and save/reload. Do not assert the experimental guard is production-ready.

## 0.9.01 release and validation baseline

- The published GitHub alpha has a Linux x86-64 AppImage, a Windows x86-64 experimental ZIP, and SHA-256 checksums. Linux AppImage SHA-256: `732d430c1db36f6c555fda872a06792313a1a6fb5e78acf1c0db584fc0520796`; Windows ZIP: `788fac2e9fc6e9dbad1725989293fecb0b0931462227de27596701c8ce133428`.
- The Linux release was built from clean 3.0.0 source plus the released HAL patch. The bundled .NET launcher, notices and ASTC codec were assembled separately; no game or personal saves were included. In Ubuntu 22.04 Docker both HAL and stock Builder windows opened, and the game-free normal/AMD FSR 4 player-build dry runs found all required files. No fresh in-game run of that exact release AppImage was performed.
- The Windows ZIP is self-contained for the launcher, includes integrated Hookshot source and ARM’s verified Windows ASTC encoder, and was cross-built on Linux. It has **not** been run or tested on Windows; building Hookshot-Dev requires the additional Windows compiler, Python packages and Builder tools described in its included instructions. Do not describe Windows as verified.
- HAL AppImage updates are manual. The alpha deliberately does not use upstream Hookshot update manifests or embed a misleading Forgejo zsync URL; it retains the stock Builder and excludes local `work/` and save fixtures. Design and verify HAL-owned update hosting before enabling automatic updates. Keep the user-facing warning about updating Hookshot and the randomizer.
- The clean release-source launcher UI suite passed, including the Information tab and warnings. A full upstream suite before release reported 833 passing, 12 failing or timing out, and 107 skipped. The two packaging source-shape failures were subsequently corrected and passed individually. The remaining investigation included unavailable .NET 8, Python `lz4`, and `lld`, a renderer target-retention failure and a long `test_vbytes.py` timeout. A later 120-second timeout run also timed out a handoff-thread test that passed in the longer run. Do not report the full suite as green; rerun on the supported 3.0.2 toolchain and investigate each remaining failure.
